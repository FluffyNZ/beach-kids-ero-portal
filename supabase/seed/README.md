# ERO criteria seed

`seed_criteria.sql` in this folder loads the official ERO criteria (C1,
PF1, HS1, GMA1 …) into the `ero_criteria` table. **It is now populated**
from the official "ERO Self-Audit Checklists for Services Licensed under
the 2008 Regulatory Framework – January 2022" document (published by the
Education Review Office), which Beach Kids supplied directly.

Every `official_requirement` value is transcribed **verbatim** from that
document — bullet points preserved, paragraph breaks preserved, nothing
reworded, simplified, combined, removed, or invented, per the brief.

Run it after `0001_init.sql`, `0002_rls.sql` and `0003_seed_sections.sql`
have been applied. It is idempotent (`on conflict (code) do update`), so
re-running it is always safe.

## Important — 13 codes are Beach Kids navigation identifiers, not official ERO numbers

The source document explicitly numbers most criteria ("Criterion C1",
"Criterion PF1", "Criterion HS1", "Criterion GMA1" …), but 13 tickable
requirements appear only under a plain numbered heading with **no
"Criterion X" label of their own**:

- **Curriculum (3):** `C14` "Documentation of Compliance (C1–C13)", `C15`
  "Curriculum Framework — The Principles", `C16` "Curriculum Framework —
  The Strands"
- **Premises and Facilities (2):** `PF39` "Access for Persons with
  Disabilities", `PF40` "Swimming Pool Requirements"
- **Governance, Management and Administration (8):** `GMA13` Immunisation
  Policies and Procedures, `GMA14` Privacy Act Compliance, `GMA15` Human
  Rights Act Compliance, `GMA16` Staff Appointments and Teacher
  Registration Review, `GMA17` Police Vetting, `GMA18` Fit and Proper
  Person — Change of Circumstances, `GMA19` Mandatory Reporting to the
  Teaching Council, `GMA20` Children's Act 2014 — Safety Checking of
  Workforce

Health and Safety has no such gaps — HS1 through HS34 are all explicitly
numbered "Criterion HS#" in the source.

For these 13 items only, the code (e.g. `C14`) is a Beach Kids-assigned
identifier continuing that section's numbering sequence, used purely for
navigation/routing inside this app — it is **not** an ERO-issued criterion
number. The requirement **text** for these 13 is still 100% verbatim from
the source document; only the numeric label was assigned by Beach Kids
because ERO itself left these particular items unlabelled. Each affected
row's `source_reference` column states this explicitly (e.g. "No individual
ERO criterion number in the source — code 'C14' is a Beach Kids navigation
identifier only; requirement text is verbatim.") so it's always visible
which numbers are ERO's own and which aren't.

## Compliance status on load

Every criterion is seeded with no row in `criterion_assessments`, which the
app treats as **Not Assessed** (compliance) / **Missing** (evidence) by
default — see `DEFAULT_ASSESSMENT` in `src/lib/types.ts`. Nothing is
pre-marked compliant, and no Beach Kids evidence, staff, child, or parent
information has been invented or attached. All of that gets entered through
the app itself as the self-audit proceeds.

## Regenerating this file

This file was generated by a one-off Python script
(`generate_seed.py`, not part of the app, kept outside this repo) that
transcribes each criterion from the source PDF's extracted text and writes
the SQL with correct string escaping. It does not need to be re-run unless
the source document itself changes.
